# 实现路线与完成标准

此文描述后续实施顺序，不表示功能已实现。

## 1. 离线双角色 PvP 验证

先实现可禁用的本地探针，枚举玩家类、控制器、阵营组件、生命属性与伤害入口。通过 UE4SS 反射确认签名，避免仅凭字符串地址写内存。生成第二角色，隔离控制、相机与锁定。逐项验证普通攻击、重击、投射物、闪避无敌、格挡、弹反、受击、死亡、复活。每次只改变一项设置并记录前后值。

完成标准：同场两个角色可双向命中，结算符合规则，个人存档不变，无全局剧情/慢动作副作用。失败时定位阵营过滤、碰撞通道或伤害计算器中的具体阻断点。

## 2. 游戏适配层

建议模块：GameAdapter（UObject 与 EntityId 映射）、CombatAuthority（攻击验证和结果）、RoomSession（房间及对局状态）、PlayerRoster/Hud（全员血条）、Transport（传输）。

先实现两人局域网。远端动作与伤害必须去重，不能让本地原生碰撞和网络 CombatResult 同时扣血。只由房主确认生命和胜负。输入即刻表现，最终状态由房主校正；不能强制等待所有玩家输入齐全。

完成标准：两个独立游戏进程的玩家位置、动作、生命和死亡结果一致。

## 3. DirectHost

实现 NetworkContracts.h 的直连适配器、连接身份、版本/地图/预设校验，以及房主创建和玩家加入。首版可使用明确的地址加入方式，公网打洞、平台好友和邀请属于后续能力，不能把局域网直连等同于完整公网 P2P。

## 4. Relay

同一协议增加中继适配器。服务器不依赖 UE、游戏资产或本机游戏路径；维护房间、成员身份、房主标识、消息路由和流量上限。连接建立时分配身份，禁止客户端伪造发送者。房主发一份广播快照，中继分发给其他成员。

完成标准：直连和中继运行同样的对局用例；房主上行不随广播目标数量线性重复发送同一快照。延迟和丢包改善必须实测，不作预设保证。

## 5. 竞技场、预设和 HUD

先支持一个经过确认的 Boss 战场景作为空竞技场，再扩展地图白名单。场景需处理 Boss/剧情生成、空气墙、出生点和重置。统一角色配置只影响临时对局状态。左上角按固定玩家列表显示生命与掉线状态；禁用本地剧情死亡自动读档等冲突行为。

## 6. 网络故障验证

分别测试单个慢客户端、房主游戏线程停顿、房主上行丢包、中继掉线、乱序、事件重传、重连、旧对局消息和晚加入。记录 RTT、丢包、发送队列、房主 tick 和状态修正次数。首版明确房主失联结束对局；迁移或独立判定服务另立里程碑。
